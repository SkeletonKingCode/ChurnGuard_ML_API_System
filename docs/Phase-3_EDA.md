# Phase 3: EDA Insights

## Run
To obtain the automatically generated report and complete Phase 3:
```bash
uv run src/data/eda.py
```

For source and detailed version of below see: `reports/EDA_REPORT.md` and `reports/figures/`, generated by
`src/data/eda.py` against the 3-way joined dataset (7,043 rows, 21 cols).

## Data quality
- No fully-null columns, no duplicate `CustomerID` or duplicate rows.
- `TotalCharges` has 11 missing values (0.16% of rows), all at `Tenure = 0`
  (brand-new customers, no billing history yet). Confirmed in Phase 2.
- IQR outlier check on `Tenure`, `MonthlyCharges`, `TotalCharges` found
  0 outliers on all three — the numeric ranges are well-behaved, no
  capping/winsorizing needed before modeling.

## Class balance
- Churn: 5,174 No (73.46%) / 1,869 Yes (26.54%).
- Moderately imbalanced, not severe. class_weight or SMOTE (per handbook
  Section 7) is still warranted given Recall is the primary metric.

## Strongest signals found
1. **Contract type is the single strongest driver.** Churn rate is ~43%
   for month-to-month contracts vs ~11% for one-year and ~3% for two-year.
   This alone will likely be a top feature for any tree-based model.
2. **Tenure correlates negatively with churn** (r = -0.35, numeric-only
   correlation). Newer customers churn more — consistent with the
   contract-type finding, since month-to-month customers tend to be newer.
3. **MonthlyCharges correlates positively** (r = 0.19) — higher bills,
   somewhat higher churn risk.
4. **TotalCharges correlates negatively** (r = -0.20) — largely a proxy for
   tenure (longer-tenured customers accumulate more total charges), not
   necessarily an independent signal. Watch for multicollinearity with
   Tenure in Phase 5/6.
5. **SeniorCitizen** has a weak positive correlation (r = 0.15).

## Distributional notes
- Tenure by churn is bimodal for churners: a large spike at very low
  tenure (new customers leaving fast), tapering off — consistent with
  finding #2.
- MonthlyCharges by churn shows churners skew toward the higher end of
  the charge range, non-churners cluster more at the low end (likely
  customers with fewer add-on services).

## Carried into Phase 4/5
- `TotalCharges`: needs numeric coercion + imputation for the 11 missing
  rows (impute as 0 or `MonthlyCharges * Tenure`, both defensible since
  Tenure = 0 for all of them).
- Multicollinearity risk between `Tenure` and `TotalCharges` — consider
  dropping one or engineering a ratio feature instead of using both raw.
- `ContractType` is a strong categorical candidate for encoding as
  ordinal (Month-to-month < One year < Two year) rather than one-hot,
  given the clear monotonic churn-rate relationship.
